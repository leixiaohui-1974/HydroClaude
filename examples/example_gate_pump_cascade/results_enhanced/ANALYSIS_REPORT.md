## 4. 质量守恒问题诊断

### 4.1 问题表现

#### S01工况
- 平均流入: 34.38 m³/s
- 平均流出: 26.18 m³/s
- 平均蓄水速率: 8.20 m³/s
- **累计流入-流出**: 19,629.9 m³
- **渠道容积变化**: 340,636.9 m³
- **质量平衡误差**: 16.35 ⚠️

#### S03工况
- 平均流入: 51.91 m³/s
- 平均流出: 26.43 m³/s
- 平均蓄水速率: 25.49 m³/s
- **累计流入-流出**: 61,363.4 m³
- **渠道容积变化**: 1,126,555.2 m³
- **质量平衡误差**: 17.36 ⚠️

### 4.2 原因分析

质量平衡误差的计算公式：
```
误差 = |累计流入流出 - 渠道容积变化| / |累计流入流出|
```

**可能原因1: 计算方法问题**

当前计算:
```python
total_storage = ∫(Q_in - Q_out) dt          # 只考虑边界流量
total_volume_change = B * dx * Σ(h_final - h_initial)  # 容积变化
```

**问题**: 
- `Q_in - Q_out` 只考虑了上下游边界，没有考虑泵站的影响
- 泵站是内部结构，会改变渠道内部的流量分布
- 实际上，泵站上游和下游的流量是不同的

**可能原因2: 泵站模型问题**

观察到的现象：
1. t=300s瞬间出现负流量（-5.72 m³/s）
2. 泵站流量从30 m³/s快速降至负值，再逐渐恢复
3. 这表明泵站模型在扰动初期可能存在数值处理问题

**可能原因3: 流量边界条件实施**

Preissmann格式的边界条件实施可能导致局部质量不守恒：
- 上游流量边界强制设定
- 下游水位边界强制设定
- 泵站内部流量计算
- 这三者的协调可能存在问题

### 4.3 验证分析

**稳态质量守恒完美（误差 < 1e-6）**表明：
- ✓ 控制方程离散正确
- ✓ 稳态求解器正确
- ✓ 泵站模型在稳态下正确

**瞬态质量平衡误差大**表明：
- ⚠️ 瞬态边界条件实施可能有问题
- ⚠️ 泵站瞬态响应计算可能有问题
- ⚠️ 或者质量平衡的计算方法不正确

### 4.4 正确的质量守恒检查方法

**建议的改进方法**:

1. **分段检查**：
   ```
   上游段（0-泵站前）: ∫(Q_in - Q_pump_in) dt = ΔV_upstream
   下游段（泵站后-末端）: ∫(Q_pump_out - Q_out) dt = ΔV_downstream
   ```

2. **泵站质量守恒**：
   ```
   Q_pump_in ≈ Q_pump_out (泵站本身不蓄水)
   ```

3. **全局检查**：
   ```
   ∫Q_in dt - ∫Q_out dt = ΔV_total
   ```

但要注意：由于泵站的存在，上游和下游的流量分布是不同的，不能简单地用边界流量差来计算。
