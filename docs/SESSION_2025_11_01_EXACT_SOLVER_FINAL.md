## 2. 技术发现

### 2.1 崩溃的根本原因

**位置**: `solvers/riemann_exact.py:344-348, 373-378`

**机制**:
```
稀疏波采样 → c→0 → h=c²/g→0 → u=Q/(h*B)→∞ → 极端通量 → 质量爆炸
```

**代码问题**:
```python
elif s <= S_tail_L:
    u = (u_L + 2.0 * c_L + 2.0 * s) / 3.0
    c = (u_L + 2.0 * c_L - s) / 3.0
    h = c**2 / g  # ❌ 没有检查h < eps_dry
    return h, u
```

### 2.2 为什么CFL=0.1延迟了崩溃？

- CFL=0.5时，dt≈0.2s，在t≈0.3s就崩溃
- CFL=0.1时，dt≈0.045s，延迟到t≈1.8s
- **时间步长更小 → 稀疏波演化更慢 → 延迟h→0的出现**
- 但这只是延迟，不是解决方案

### 2.3 对比HLL求解器

HLL为什么不崩溃？
- 简化的通量公式，内置数值耗散
- 不需要精确采样稀疏波内部
- 对h→0有隐式保护

## 4. 修复方案（未实施）

### 方案A: 添加干床保护（推荐）

```python
def _sample_solution(...):
    # ... existing code ...

    elif s <= S_tail_L:
        # Inside rarefaction fan
        u = (u_L + 2.0 * c_L + 2.0 * s) / 3.0
        c = (u_L + 2.0 * c_L - s) / 3.0

        # ✅ 保护c不小于干床阈值
        c = max(c, np.sqrt(g * eps_dry))
        h = c**2 / g

        # ✅ 双重保护
        if h < eps_dry:
            return eps_dry, 0.0

        return h, u
```

**优点**:
- 直接解决根本问题
- 符合Toro (2009)标准实现
- 实施简单

**缺点**:
- 需要全面验证测试
- 在干床附近可能影响精度
- 时间成本：估计2-4小时

1. **干床处理的重要性**
   - 所有Riemann求解器必须处理h→0
