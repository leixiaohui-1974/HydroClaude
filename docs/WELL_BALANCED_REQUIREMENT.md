## 🔍 根本原因

### Well-Balanced属性定义

**Well-Balanced格式**（也称C-property）要求数值格式能够精确保持静水平衡：

**静水平衡状态**:
- 水面水平: η = h + z_b = constant
- 流速为零: u = 0
- 压力梯度与重力源项精确平衡:
  ```
  ∂/∂x(gh²/2) = -gh ∂z_b/∂x
  ```

**当前求解器的问题**:
- 离散格式未能精确平衡压力项和源项
- 在坡度河床上产生O(1)量级的虚假流速
- 虚假流速累积导致数值爆炸

### Lake at Rest测试证据

根据`LAKE_AT_REST_TEST_REPORT.md`:

| 测试工况 | 底坡/变化 | 水面扰动 | 状态 |
|---------|----------|---------|------|
| P0.1 平底 | 0 | ~1e-14 m | ✅ |
| P0.2 缓坡 | 2m凸起 | 3.99 m | ❌ |
| P0.3 陡坡 | 5m台阶 | 11.35 m | ❌ |

**结论**: 当前格式对变化底坡产生米级非物理扰动。

### 河道洪水演进的特点

50km河道，坡度0.0005:
- **总高程变化**: Δz_b = 50000 × 0.0005 = 25 m
- **Froude数**: Fr = u/√(gh) ≈ 0.2 (亚临界流)
- **时间尺度**: 18小时模拟

在长时间、长距离模拟中，米级虚假扰动会累积并导致系统崩溃。

## 📚 理论背景

### C-property (Well-Balanced属性)

**Bermudez & Vazquez (1994)**: 数值格式应精确保持静水平衡。

**Audusse et al. (2004)**: Hydrostatic Reconstruction方法
```
重构思想:
  在界面处分离"动力学水深"和"静力学水深"

  h_L* = h_L - max(0, z_bR - z_bL)
  h_R* = h_R - max(0, z_bL - z_bR)

  用h*计算通量，恢复C-property
```

### 实现要点

1. **界面重构**:
   - 在每个cell界面处重新定义有效水深
   - 隐式处理底坡源项

2. **源项离散**:
   - 源项S = -gh ∂z_b/∂x应与通量项精确平衡
   - 通常采用upwind方式离散

3. **正定性保持**:
   - 重构后仍需保证h* ≥ 0
   - 与湿干界面处理协调

## 🎯 适用场景

### 需要Well-Balanced的场景

1. **河道洪水演进** ⭐ (本案例)
   - 长距离传播
   - 缓坡河床
   - 长时间模拟

2. **潮汐河口**:
   - 静水基础状态
   - 潮汐扰动叠加

3. **水库调度**:
   - 变坡库区
   - 缓变流分析

### 不需要Well-Balanced的场景

1. **溃坝** (激波主导):
   - 极短时间（<10s）
   - 激波控制，源项次要

2. **平底渠道**:
   - z_b = constant
   - 无源项平衡问题

3. **陡坡急流**:
   - 大Froude数
   - 对流项主导
