## 📊 性能瓶颈分析

### 潜在瓶颈 (预期)

#### 1. 计算密集型操作

**问题**: 复杂模拟计算可能导致响应时间过长

**影响端点**:
- POST /api/solve/steady-flow
- POST /api/solve/advanced

**建议优化**:
- ✅ 使用异步任务队列 (Celery)
- ✅ 实现结果缓存
- ✅ 优化算法复杂度
- ✅ 增加计算资源

---

#### 2. 数据库查询

**问题**: 大量并发读操作可能导致数据库瓶颈

**影响端点**:
- GET /api/knowledge-base
- GET /api/cases
- GET /api/learning-progress

**建议优化**:
- ✅ 添加数据库索引
- ✅ 实现查询缓存 (Redis)
- ✅ 使用读写分离
- ✅ 优化 SQL 查询

---

#### 3. 前端资源加载

**问题**: 大型 JavaScript 包可能导致首屏加载慢

**影响页面**:
- 所有页面 (特别是建模和可视化页面)

**建议优化**:
- ✅ 代码分割 (Code Splitting)
- ✅ 懒加载 (Lazy Loading)
- ✅ 资源压缩 (Gzip/Brotli)
- ✅ CDN 加速
- ✅ 图片优化

---

## 📝 如何运行性能测试

### 后端性能测试 (Locust)

#### 1. Web UI 模式 (推荐)

```bash
# 启动 Locust Web UI
locust -f locustfile.py --host=http://localhost:8000

# 访问 http://localhost:8089
# 配置参数:
#   - Number of users: 50 (正常负载) / 200 (峰值负载)
#   - Spawn rate: 5 (正常) / 20 (峰值)
#   - Run time: 120s (正常) / 60s (峰值)
```

---

#### 2. 无头模式 (CI/CD)

```bash
# 稳定负载测试
locust -f locustfile.py --host=http://localhost:8000 --headless \
       --users 50 --spawn-rate 5 --run-time 120s \
       --html=reports/locust_steady_load.html \
       --csv=reports/locust_steady_load

# 峰值负载测试
locust -f locustfile.py --host=http://localhost:8000 --headless \
       --users 200 --spawn-rate 20 --run-time 60s \
       --html=reports/locust_spike_load.html \
       --csv=reports/locust_spike_load

# 持续负载测试
locust -f locustfile.py --host=http://localhost:8000 --headless \
       --users 30 --spawn-rate 3 --run-time 300s \
       --html=reports/locust_sustained_load.html \
       --csv=reports/locust_sustained_load
```

---

#### 3. API 专项测试

```bash
# 只测试 API (排除前端)
locust -f locustfile.py --host=http://localhost:8000 --headless \
       --users 100 --spawn-rate 10 --run-time 60s \
       --tags api \
       --html=reports/locust_api_only.html
```
