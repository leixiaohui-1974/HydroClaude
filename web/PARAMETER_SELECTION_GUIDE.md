## 📊 核心参数详解

### 1. 几何参数

#### 1.1 渠道宽度 (width)
```
参数: width
单位: 米 (m)
范围: 0.1 - 1000 m
```

**选择指南**:
- 小型渠道: 1-10 m
- 中型河道: 10-50 m
- 大型河流: 50-500 m

**影响**:
- 宽度越大，水深越小（给定流量）
- 影响Froude数和流态

**示例**:
```json
"width": 10.0  // 中型明渠
```

---

#### 1.2 渠道长度 (length)
```
参数: length
单位: 米 (m)
范围: 10 - 100000 m
```

**选择指南**:
- 短渠道: 100-1000 m（快速测试）
- 中等河段: 1000-10000 m（标准模拟）
- 长河道: 10000-100000 m（区域模拟）

**影响**:
- 长度决定波的传播时间
- 影响所需模拟时长

**示例**:
```json
"length": 1000.0  // 1公里河段
```

---

#### 1.3 网格数 (n_cells)
```
参数: n_cells
单位: 无量纲
范围: 10 - 10000
```

**选择指南**:

| 网格数 | 空间分辨率 | 计算时间 | 适用场景 |
|--------|----------|---------|---------|
| 50-100 | 粗糙 | 快 < 0.5s | 快速测试 |
| 100-200 | 标准 | 中 < 2s | 常规模拟 |
| 200-500 | 精细 | 慢 < 10s | 详细分析 |
| 500-1000 | 很精细 | 很慢 < 60s | 研究级 |
| > 1000 | 极精细 | 极慢 > 60s | 特殊需求 |

**网格尺寸计算**:
```
dx = length / n_cells

例如: 1000m / 100 = 10m/网格
```

**稳定性建议**:
- 新手: 100个网格
- 标准: 200个网格
- 高精度: 500+个网格

**示例**:
```json
"n_cells": 100  // 标准配置
```

---

### 2. 时间参数

#### 2.1 模拟时间 (t_end)
```
参数: t_end
单位: 秒 (s)
范围: 1 - 86400 s (24小时)
```

**选择指南**:

| 问题类型 | 推荐时长 | 说明 |
|---------|---------|------|
| 快速测试 | 10-30s | 验证配置 |
| 溃坝 | 5-60s | 激波传播 |
| 稳态流 | 60-600s | 达到稳态 |
| 洪水 | 3600-86400s | 洪峰演进 |

**估算方法**:
```
传播时间 ≈ length / wave_speed
wave_speed ≈ √(g * h) ≈ 7 m/s (h=5m)

例如: 1000m河道 → 约150秒传播时间
```

**示例**:
```json
"t_end": 60.0  // 1分钟模拟
```

---

#### 2.2 CFL数 (cfl)
```
参数: cfl
单位: 无量纲
范围: 0.1 - 0.9
推荐: 0.3 - 0.5
```

**什么是CFL数？**
CFL (Courant-Friedrichs-Lewy) 条件控制时间步长：
```
dt = cfl * dx / max_wave_speed
```

**选择指南**:

| CFL值 | 稳定性 | 计算时间 | 适用场景 |
|------|--------|---------|---------|
| 0.1-0.2 | 极高 | 慢 | 极端不稳定问题 |
| 0.3 | 高 | 中 | **推荐新手** ⭐ |
| 0.4-0.5 | 中 | 快 | 经验用户 |
| > 0.5 | 低 | 很快 | ⚠️ 风险高 |

**关键规则**:
- ⚠️ **CFL > 1.0 必然不稳定！**
- 激波/溃坝问题: 使用 CFL ≤ 0.3
- 稳定流: 可用 CFL = 0.5
- 出现不稳定: 降低CFL是第一选择

**示例**:
```json
"cfl": 0.3  // 保守稳定
```

### 3. 物理参数

#### 3.1 底坡 (slope)
```
参数: slope
单位: 无量纲 (m/m)
范围: 0 - 0.1
```

**选择指南**:

| 坡度类型 | 数值范围 | 示例 |
|---------|---------|------|
| 平坦 | 0 - 0.0001 | 湖泊、水库 |
| 缓坡 | 0.0001 - 0.001 | 平原河流 |
| 中坡 | 0.001 - 0.01 | 山区河流 |
| 陡坡 | 0.01 - 0.1 | 山洪沟道 |

**影响**:
- 坡度越大，流速越快
- 陡坡可能导致数值不稳定
- 坡度 > 0.01 建议使用 Well-Balanced 格式

**示例**:
```json
"slope": 0.001  // 0.1% 缓坡
```

---

#### 3.2 曼宁系数 (manning_n)
```
参数: manning_n
单位: s/m^(1/3)
范围: 0.01 - 0.1
```

**选择指南**:

| 表面类型 | 曼宁系数 | 说明 |
|---------|---------|------|
| 光滑混凝土 | 0.010-0.013 | 最小阻力 |
| 普通混凝土 | 0.013-0.017 | 标准渠道 |
| 碎石/卵石 | 0.025-0.035 | **常用** ⭐ |
| 天然河道 | 0.030-0.050 | 粗糙河床 |
| 有植被河道 | 0.050-0.100 | 大阻力 |

**影响**:
- n值越大，阻力越大，流速越慢
- 影响水深和流态
- 稳态流中非常重要

**示例**:
```json
"manning_n": 0.025  // 碎石河床
```

---

### 4. 数值参数

#### 4.1 空间精度 (order)
```
参数: order
单位: 无量纲
可选值: 1, 2
默认: 2
```

**选择指南**:

| 精度阶数 | 精度 | 稳定性 | 适用场景 |
|---------|------|--------|---------|
| 1阶 | 低 | **高** ⭐ | 新手、不稳定问题 |
| 2阶 | 高 | 中 | 经验用户、精细模拟 |

**对比**:
```
1阶格式:
  优点: 稳定性极好，不产生非物理振荡
  缺点: 数值耗散较大，精度较低

2阶格式 (MUSCL):
  优点: 精度高，捕捉激波能力强
  缺点: 可能在极端条件下不稳定
```

**建议**:
- 💡 **首次尝试用1阶**
- 稳定后再尝试2阶
- 出现振荡/不稳定 → 立即切换到1阶

**示例**:
```json
"order": 1  // 保守选择
```

---

#### 4.2 Numba加速 (use_numba)
```
参数: use_numba
单位: 布尔值
可选值: true, false
默认: true
```

**性能对比**:
```
use_numba = true:  0.17秒  ⚡⚡⚡
use_numba = false: 1.50秒  ⚡

加速比: 约 8.8倍
```

**建议**: 始终使用 `true`（除非调试）

---

#### 4.3 Well-Balanced格式 (well_balanced)
```
参数: well_balanced
单位: 布尔值
可选值: true, false
默认: false
```

**什么时候需要？**

| 底坡类型 | 需要WB | 说明 |
|---------|--------|------|
| 平底 (S=0) | ❌ 不需要 | 标准格式足够 |
| 缓坡 (< 0.001) | ❌ 不需要 | 影响很小 |
| 中坡 (0.001-0.01) | ⚠️ 可选 | 长时间模拟建议启用 |
| 陡坡 (> 0.01) | ✅ 需要 | 必须启用 |
| 变底地形 | ✅ 需要 | 避免虚假流动 |

**示例**:
```json
"well_balanced": false  // 缓坡不需要
```

### 5. 初始条件

#### 5.1 均匀初始条件
```json
"initial_conditions": {
  "type": "uniform",
  "h": 5.0,    // 初始水深 (m)
  "Q": 20.0    // 初始流量 (m³/s)
}
```

**适用**: 稳态流、常规模拟

**稳定性提示**:
- Q值应与边界条件匹配
- 避免初始激波

---

#### 5.2 溃坝初始条件
```json
"initial_conditions": {
  "type": "dam_break",
  "h_left": 10.0,      // 上游水深 (m)
  "h_right": 1.0,      // 下游水深 (m)
  "dam_position": 500.0 // 坝位置 (m)
}
```

**适用**: 溃坝、激波问题

**稳定性提示**:
- 水深比 < 15:1
- 使用低CFL (0.25-0.3)
- 使用1阶格式

---

### 6. 边界条件

#### 6.1 流量边界
```json
"left": {
  "type": "Q",
  "value": 20.0  // m³/s
}
```

**适用**: 上游入流

---

#### 6.2 水深边界
```json

  "value": 5.0  // m

```

**适用**: 下游水位控制

---

#### 6.3 自由边界
```json

  "type": "free"
}
```

**适用**: 溃坝、透射边界

## ⚠️ 数值稳定性指南

### 黄金法则

1. **首次模拟必须保守**
   ```json
   {
     "cfl": 0.3,
     "order": 1,
     "n_cells": 100,
     "Q_initial": < 50 m³/s
   }
   ```

2. **渐进式提高难度**
   ```
   保守配置 → 标准配置 → 高精度配置
   ```

3. **出问题立即降级**
   ```
   不稳定 → 降低CFL → 切换1阶 → 减小流量
   ```

### 稳定性检查清单

运行前检查：
- [ ] CFL ≤ 0.5
- [ ] 初始条件与边界条件匹配
- [ ] 流量合理 (< 100 m³/s 新手)
- [ ] 网格数合理 (100-500)
- [ ] 激波问题使用1阶

## 🔧 参数调优流程

### 标准流程

```
步骤1: 使用模板
  ↓
步骤2: 小规模测试
  ├─ 成功 → 步骤3
  └─ 失败 → 降低CFL/切换1阶
  ↓
步骤3: 调整物理参数
  ├─ 宽度、长度、坡度
  └─ 保持数值参数不变
  ↓
步骤4: 增大规模
  ├─ 增加网格数
  ├─ 延长模拟时间
  └─ 监控稳定性
  ↓
步骤5: 提高精度（可选）
  └─ 2阶格式
```

### 示例：从保守到高精度

```python
# 阶段1: 保守配置（测试）
config = {
    "n_cells": 100,
    "t_end": 30.0,
    "cfl": 0.3,
    "order": 1,
    "Q": 20.0
}

# 阶段2: 标准配置（成功后）
config = {
    "n_cells": 200,
    "t_end": 60.0,
    "cfl": 0.5,
    "order": 1,  # 保持1阶
    "Q": 50.0
}

# 阶段3: 高精度配置（经验用户）
config = {
    "n_cells": 500,
    "t_end": 120.0,
    "cfl": 0.3,  # 降回0.3
    "order": 2,  # 尝试2阶
    "Q": 50.0
}
```

## 🚨 常见问题排查

### 问题1: "Numerical instability detected"

**症状**: 仿真在某时刻崩溃

**可能原因**:
1. CFL数过大
2. 流量过大
3. 2阶格式不稳定
4. 初始条件不匹配

**解决方案**（按顺序尝试）:
```python
# 方案1: 降低CFL
"cfl": 0.5 → 0.3 → 0.2

# 方案2: 切换1阶
"order": 2 → 1

# 方案3: 减小流量
"Q": 100 → 50 → 20

# 方案4: 匹配初始和边界
"initial_conditions": {"Q": 20.0}
"boundary_conditions": {"left": {"value": 20.0}}
```

---

### 问题2: "RuntimeWarning: overflow"

**症状**: 数值溢出到inf

**原因**: 数值爆炸，通常由大流量引起

**解决方案**:
```python
# 立即降低流量
"Q": 100 → 20

# 并降低CFL
"cfl": 0.5 → 0.3

# 使用1阶
"order": 1
```

---

### 问题3: 质量不守恒

**症状**: `mass_conservation_error > 1%`

**原因**:
1. 边界条件错误
2. 初始条件不合理
3. 时间步长过大

**解决方案**:
```python
# 检查边界
"boundary_conditions": {
    "left": {"type": "Q", "value": 20.0},   # 确保类型正确
    "right": {"type": "h", "value": 5.0}    # 不要同时用两个Q
}

# 检查初始条件
"initial_conditions": {
    "h": 5.0,  # 正数
    "Q": 20.0  # 匹配左边界
}

# 降低CFL
"cfl": 0.3
```

---

### 问题4: 模拟太慢

**症状**: 计算时间过长

**原因**:
1. 网格过多
2. CFL过小
3. 模拟时间过长
4. Numba未启用

**解决方案**:
```python
# 减少网格
"n_cells": 500 → 200

# 增大CFL（但不超过0.5）
"cfl": 0.2 → 0.3 → 0.4

# 缩短时间
"t_end": 3600 → 600

# 启用Numba
"use_numba": true  # ⚡ 8倍加速
```

---

### 问题5: 结果不合理

**症状**: 水深、流速异常

**检查清单**:
```python
# 1. 检查单位
"width": 10.0,    # 米，不是厘米
"Q": 20.0,        # m³/s，不是L/s

# 2. 检查物理合理性
Froude数 = V / √(gh)  # 应在 0.1-2.0
流速 = Q / (B * h)    # 应在 0.1-10 m/s

# 3. 检查边界
上游边界应比下游高（有坡度）
```
