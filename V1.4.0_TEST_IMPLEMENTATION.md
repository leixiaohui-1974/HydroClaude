### 1.2 Configuration Files

```typescript
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';

export default defineConfig({
```

## 4. Running the Tests

### 4.1 Installation

First, install the test dependencies:

```bash
cd web/frontend
npm install
```

This will install:
- `vitest` - Test runner
- `@testing-library/react` - React testing utilities
- `@testing-library/user-event` - User interaction simulation
- `@testing-library/jest-dom` - Custom matchers
- `jsdom` - DOM implementation for Node.js
- `@vitest/ui` - Visual test UI
- `@vitest/coverage-v8` - Code coverage

### 4.2 Running Tests

**Watch Mode** (recommended during development):
```bash
npm test
```
- Runs tests in watch mode
- Re-runs tests when files change
- Interactive CLI

**UI Mode** (visual interface):
```bash
npm run test:ui
```
- Opens browser-based test UI
- Visual test results
- Interactive test filtering
- Component tree visualization

**Run Once** (CI/CD):
```bash
npm run test:run
```
- Runs all tests once
- Exits with code 0 (success) or 1 (failure)
- Suitable for CI pipelines

**Coverage Report**:
```bash
npm run test:coverage
```
- Generates code coverage report
- Creates HTML report in `coverage/` directory
- Shows line, branch, function, and statement coverage

## 6. Test Maintenance

### 6.1 Adding New Tests

When adding new visualization features:

1. **Create test file** in `__tests__/` directory next to component
2. **Follow naming convention**: `ComponentName.test.tsx`
3. **Use describe blocks** to organize tests by category
4. **Write descriptive test names** that explain what is being tested
5. **Test user interactions**, not implementation details
6. **Mock heavy dependencies** (Plotly, etc.)

### 6.2 Test Best Practices

✅ **DO:**
- Test from user's perspective
- Use accessible queries (getByRole, getByLabelText)
- Test user interactions (clicks, typing, etc.)
- Use waitFor for async operations
- Mock external dependencies
- Keep tests independent

❌ **DON'T:**
- Test implementation details
- Use querySelector (prefer semantic queries)
- Share state between tests
- Test third-party libraries
- Create brittle tests with too many assertions

### 6.3 Debugging Failed Tests

**VS Code Integration:**
1. Install "Vitest" extension
2. Run tests with debugging
3. Set breakpoints in test files

**Console Logging:**
```typescript
import { screen, render } from '@testing-library/react';

render(<Component />);
screen.debug(); // Prints current DOM
```

**Test Isolation:**
```bash
# Run specific test file
npm test AnimationController.test.tsx

# Run specific test
npm test -t "should render all control buttons"
```

## 7. Continuous Integration

### 7.1 GitHub Actions Workflow

Add to `.github/workflows/test.yml`:

```yaml
name: Test

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: cd web/frontend && npm ci
      - run: cd web/frontend && npm run test:run
      - run: cd web/frontend && npm run test:coverage
      - uses: codecov/codecov-action@v3
        with:
          files: ./web/frontend/coverage/coverage-final.json
```

### 7.2 Pre-commit Hooks

Add to `package.json`:

```json
{
  "husky": {
    "hooks": {
      "pre-commit": "npm run test:run && npm run lint"
    }
  }
}
```

## 8. Known Limitations

### 8.1 Plotly.js Mocking

- Plotly.js is mocked in tests for performance
- Visual rendering is not tested (requires E2E tests)
- 3D interactions are not tested in unit tests

**Mitigation**: Manual visual testing + future E2E tests with Playwright

### 8.2 Animation Timing

- `requestAnimationFrame` is mocked with `setTimeout`
- Exact timing behavior not tested
- 30 FPS target not verified in tests

**Mitigation**: Manual performance testing

### 8.3 Browser Compatibility

- Tests run in jsdom (not real browser)
- Cross-browser issues not detected
- CSS rendering not tested

**Mitigation**: Manual testing in target browsers (Chrome, Firefox, Safari, Edge)
